# 当前现状三栏梳理

本文档用于沉淀当前产品状态，重点区分三类内容：

1. 已落地能力
2. 半落地能力
3. 下一阶段最该产品化的能力

目标不是复述长期愿景，而是帮助团队在讨论产品方向、UI 演进、Runtime 价值和护城河时，有一份更贴近当前真实实现的对照表。

---

## 说明

- 本文档基于当前 `docs/` 里的产品文档，以及 `src/runtime/`、`src/ui/`、`src/ai-services/` 的现有实现整理。
- 这里的“已落地”指代码与体验上已经能跑通，不等于已经达到产品成熟状态。
- 这里的“半落地”指方向正确、局部已出现，但还没有形成稳定闭环。
- 这里的“下一阶段最该产品化”指最值得优先转化为用户可感知价值的能力，而不是继续停留在底层能力或概念层。

---

## 三栏总表

| 已落地能力 | 半落地能力 | 下一阶段最该产品化的能力 |
|---|---|---|
| **Runtime 基座**：`Asset / Workspace / Decision / Graph` 的最小闭环已经成立，能做状态留存、项目恢复、资产注册。 | **Graph 更深层关系**：现在有基础关系，但还没形成真正可驱动复杂编辑和复用的资产关系网络。 | **任务导向工作台模式**：先把 runtime 变成“海报模式 / 商品模式 / 空间模式”这类明确工作模式，而不是通用容器。 |
| **Dispatcher + Memory 日志链**：重要动作已统一经过 `Dispatcher`，并进入 `CreativeMemoryLayer`，能记录意图、上下文、前后状态。 | **结果级反馈闭环**：现在主要记录“做了什么”，但还没稳定记录“哪些结果被接受、保留、导出、复用”。 | **结果驱动推荐**：推荐不只看历史动作，还要看最终是否被采用，形成真正的 reward loop。 |
| **Intent 归纳**：`IntentEngine` 已能把部分参数行为抽象成语义意图，如食物增强、赛博朋克、突出主体。 | **意图体系仍偏启发式**：目前规则可用，但还是 preset + heuristic 为主，离“任务语义模型”还有距离。 | **任务语义库**：把意图从风格词升级成任务节点，比如“换商品”“改价格区”“生成活动版式”“回贴场景”。 |
| **SemanticRecommender 推荐雏形**：已经会基于上下文、历史 intent、局部调参，动态给出推荐。 | **推荐仍偏灵感卡片**：更像“建议你试试这个风格/配方”，还不是“下一步最优动作编排”。 | **工作流编排推荐**：让系统直接推荐下一步操作顺序，而不是只推荐参数或风格。 |
| **Fusion Editor / Inspiration Capsule UI**：推荐已经进入界面，不是后台想法；用户选中图层后能看到建议、状态、快捷动作。 | **UI 还没形成主工作流**：现在是“聪明的编辑器”，但还不是某一类任务的默认操作台。 | **主任务界面收束**：围绕一个高频任务，把界面重心固定下来，让用户第一次就知道该怎么继续。 |
| **Magic Layers 入口能力**：全图语义分析、自动选层、批量提取、图层编辑、回贴验证，这条链路已经在工作。 | **图层后续生产链还不够强**：提取之后能改，但“批量变体、模板复用、跨项目资产调用”还没完全长出来。 | **资产化后的第一高频动作**：必须明确图层拆出来之后，用户最常做的第一件事是什么，并围绕它产品化。 |
| **资产留存与版本演化**：本地保存、版本回退、变体记录这些已经有雏形。 | **资产库价值还没完全释放**：现在更多是“存下来”，还没完全做到“跨项目复用 + 推荐调用 + 成组调用”。 | **资产库产品化**：把“我的常用资产 / 我的风格配方 / 我的高频组合”做成真正可调用的库。 |
| **推荐与个性化方向是成立的**：系统已经在尝试“越来越懂这个用户”。 | **个性化还主要发生在图层局部**：更像局部编辑协助，而不是整项目、整任务级个性化。 | **项目级个性化工作台**：根据用户历史任务，动态调整默认面板、推荐顺序、模板入口、常用动作。 |
| **护城河叙事主线基本成立**：不是拼模型，而是沉淀决策路径、工作习惯、资产与复用关系。 | **部分文档超前于现状**：尤其 `implicit_memory_and_telemetry.md` 更像中长期蓝图，不适合直接当“已实现说明”。 | **产品语言统一**：对外只保留一套说法，把“我们已做到什么、下一步做什么”讲得非常具体。 |

## 现阶段的核心判断

当前最扎实的部分，不是“分层更准了”，而是已经有了一个能记录、留存、推荐的视觉 Runtime 雏形。

当前最欠缺的部分，不是再多一个能力点，而是把这些能力压到一个主任务上，变成用户能明显感受到的默认工作流。

换句话说：

- 现在已经不是“有没有 Runtime”的问题，而是“Runtime 该先服务哪一种高频任务”的问题。
- 现在已经不是“有没有推荐”的问题，而是“推荐能不能从灵感卡片升级为工作流编排”的问题。
- 现在已经不是“有没有资产沉淀”的问题，而是“资产沉淀能不能转化为复用和留存”的问题。

---

## 当前最值得优先推进的三件事

### 1. 结果级反馈闭环

不仅记录用户做了什么，还要记录：

- 哪些推荐最终被采用
- 哪些结果被保留
- 哪些结果被导出
- 哪些资产被跨项目复用

这一步决定数据飞轮能不能真正从“动作记录”升级为“有效决策沉淀”。

### 2. 工作流编排推荐

从“推荐一个风格卡片”升级到：

- 当前图最适合先做什么
- 当前对象最适合先提取、先编辑还是先回贴
- 在某类任务中，下一步最可能成功的路径是什么

这一步决定推荐系统能不能从灵感层走向生产力层。

### 3. 主任务界面收束

先选择一个高频任务，把 UI 做成真正的工作台，而不是泛化的智能编辑器。

候选方向可以是：

- 商品海报 / 宣传图
- 空间资产提取与回贴
- 餐饮菜单 / 促销图
- 电商主图 / 详情页视觉变体

只有主任务足够明确，Runtime 的个性化和推荐能力才有真实的落点。

## 一个更适合当前阶段的产品表述

现阶段更适合用下面这句话定义系统：

> 我们不是在做一个只会分层的工具，而是在做一个会记录、理解并逐渐适配用户工作习惯的视觉工作 Runtime。

再进一步，下一阶段的目标可以表述为：

> 把任何现成图片转化成可编辑、可复用、可批量产出的视觉资产工程，并让系统随着用户任务不断变得更懂他。
